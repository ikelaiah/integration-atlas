# v0.5.0 Specification: Reliable Graph Exploration

## Goal

Let people move around the integration graph without changing its layout or
losing their place. Viewport controls should do the action their labels promise.

## Current gaps

- Graph nodes are placed by the automatic layout but can be dragged. Their
  positions are not persisted, so dragging them creates a temporary position
  that can snap back when graph props update.
- The page-level Zoom in control requests a fit operation, while Zoom out has
  no action.

## Decisions

- Nodes remain fixed in the automatic layout. Clicking a node selects it;
  left-button drag gestures pan the graph canvas.
- Panning works across both axes and does not select or displace nodes.
- Selection, hover, and detail-panel updates do not issue a fit operation.
- Zoom in and Zoom out change the current zoom. Fit explicitly frames the
  current graph; Reset clears selection and filters, then fits the graph.

## Acceptance criteria

- [ ] Dragging the canvas right, left, up, or down pans in that direction,
  including when the drag starts over a node.
- [ ] A drag does not select or move a node; a click still selects the node and
  opens its detail panel.
- [ ] Selecting a node and opening or closing its detail panel do not reset the
  current pan or zoom.
- [ ] Zoom in and Zoom out change zoom while retaining the current view center.
- [ ] Fit returns the current graph to a centered overview after pan and zoom.
- [ ] Reset clears selection and filters and returns the graph to a centered
  overview.
- [ ] Icon-only viewport controls expose accessible names.

## Scope boundary

Saved manual node positions, saved views, and broader graph layout changes are
deferred. Nodes continue to use the generated layout.

- [ ] Full release checks, code review, CI, and Pages verification complete
