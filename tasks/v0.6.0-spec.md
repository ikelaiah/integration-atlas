# v0.6.0 Specification: Separate Workspaces from the Demo

## Goal

People always know whether they are looking at the Northstar demo or their own
estate. Nothing done to the demo changes or removes their own discoveries.

## Current gaps

- On an empty database the web app seeds Northstar without asking and makes it
  the active workspace.
- The web app cannot create a workspace, so a folder scanned from **Scans** is
  merged into the demo. The review-workflow guide documents that flow.
- **Reset demo estate** deletes every entity and relationship in the demo
  workspace, including scanned discoveries, while scan history still lists the
  scans. It has no confirmation.
- The active workspace is not remembered after a reload, can only be changed
  from Settings, and switching keeps the previous workspace's selection,
  impact, path and scan preview state.
- A failed startup request leaves an empty app with no explanation.
- `atlas impact` and `atlas export` silently fall back to the oldest workspace,
  and `atlas scan run --workspace <id>` creates a workspace named after the id.

## Decisions

- The demo workspace is reserved for Northstar data. The API and CLI refuse to
  preview or apply a scan into it (HTTP 409), and refuse to create a regular
  workspace whose name matches the demo.
- A scan preview may name a workspace that does not exist yet. The preview
  creates it inside the rolled-back transaction, so abandoning a preview leaves
  no empty workspace. Applying the scan creates the workspace.
- `GET /api/demo` reports the demo workspace, the counts a reset restores, and
  any data in it that did not come from the demo: scan history, and entities or
  relationships whose fingerprints are not in the Northstar bundle.
- `POST /api/demo/reset` restores Northstar. Edits to demo entities and review
  decisions on demo relationships are reverted. If the workspace holds data
  from elsewhere, Atlas first keeps it as a regular workspace named
  `Northstar Education Group (kept YYYY-MM-DD)`, with all its rows and scan
  history, then creates a fresh demo workspace. Nothing is deleted.
- `POST /api/workspaces/{id}/seed-demo` and `atlas demo` use the same reset and
  remain for compatibility; the route is marked deprecated.
- The web app stores the active workspace id in browser storage, falls back to
  the first non-demo workspace, then the demo. Workspace-scoped pages remount
  on a switch.
- CLI commands that fall back to a default workspace print its name to stderr.
- No database migration: the release reads existing columns only.

## Acceptance criteria

- [x] On an empty database, the web app offers **Explore the Northstar demo**
  and **Scan your own folder**; it loads nothing until one is chosen.
- [x] Scans can target an existing non-demo workspace or a new named one; the
  demo is never offered as a target, and the API rejects it.
- [x] Previewing into a new workspace creates no workspace; applying does, and
  the app switches to it.
- [x] **Reset demo estate** shows what it reverts and, when present, what it
  will keep in a separate workspace, before asking for confirmation.
- [x] Resetting a demo workspace that holds scan results keeps those results
  and their history in the kept workspace and leaves a fresh 95-entity demo.
- [x] The sidebar shows the active workspace and switches between workspaces;
  the choice survives a reload; switching clears selection, impact, path and
  preview state.
- [x] When the API cannot be reached on startup, the app says so, suggests
  `atlas serve`, and offers Retry.
- [x] CLI fallback commands name the workspace they used; `atlas scan run`
  resolves `--workspace` by id or slug before creating one and refuses the demo.

## Out of scope

Renaming, deleting or merging workspaces, and moving discoveries between them.

## Verification

- Backend tests for scan isolation, preview without side effects, workspace
  name conflicts, both reset paths, the deprecated route and CLI messages.
- Full backend suite, Ruff, frontend type check and build, DocSprout check,
  strict audit and build, CI matrix and Docker smoke test.
- Exercise first run, scanning into a new workspace, switching, reload and
  demo reset against a running local server.
- Update README, review and comparison guides, roadmap, version metadata and
  title-free release notes.
