The Northstar demo and your own estate now stay apart.

- On a new database, the web app asks whether to explore the Northstar demo or
  scan your own folder. It no longer loads the demo without asking.
- Scans go into a workspace of your own. In **Scans**, pick an existing
  workspace or name a new one; a preview creates nothing, and applying the
  scan creates the workspace and switches to it. The API and CLI refuse to
  scan into the demo workspace.
- **Reset demo estate** asks first and says what it will do. It restores the
  sample data and reverts edits and review decisions made in the demo. It never
  deletes scan results: if an older demo workspace holds them, Atlas keeps that
  workspace as `Northstar Education Group (kept YYYY-MM-DD)`, scan history
  included, and creates a fresh demo next to it. `atlas demo` behaves the same
  way.
- Switch workspaces from the sidebar. Atlas remembers the choice after a
  reload, and switching clears the previous workspace's selection, impact,
  path and scan preview.
- If the app cannot reach its local API on startup, it says so, suggests
  `atlas serve` and offers Retry.
- `atlas impact` and `atlas export` print which workspace they used when you
  omit `--workspace`. `atlas scan run --workspace` now accepts an existing id
  or slug instead of creating a workspace named after it.

Existing databases need no migration. New `GET /api/demo` and
`POST /api/demo/reset` endpoints describe and perform the reset;
`POST /api/workspaces/{id}/seed-demo` remains as a deprecated alias. See the
[review workflow](https://ikelaiah.github.io/integration-atlas/review-workflow.html)
for the updated scan steps.
